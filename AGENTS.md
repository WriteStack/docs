# WriteStack Docs: how to write here

Public docs for WriteStack (docs.writestack.io). Built with Next.js + Fumadocs. Content lives in `content/docs`. Readers are writers using WriteStack **and AI agents** reading `/llms.txt`, `/llms-full.txt` and the `.md` version of each page. Write for both.

## Tracks

| Folder | Track | For |
| --- | --- | --- |
| `content/docs/using` | Using WriteStack | Writers using the app |
| `content/docs/account` | Account & billing | Plans, payments, cancelling |
| `content/docs/build` | Build with WriteStack | MCP, agents, (later) the API |

Sidebar order is set in each folder's `meta.json`. A new page must be added there.

## Facts come from the code

The app is at `../WriteStack` (Next.js app, Prisma). Every claim about behaviour, limits, names of buttons and settings must be checked against that code. Quote UI labels exactly as the app shows them.

- Don't guess. If you can't verify something, leave it out, or add an MDX comment `{/* TODO(orel): question */}` (invisible to readers) and list it in your report.
- Don't document things behind a feature flag or not shipped (for example native social connections, `NATIVE_PLATFORMS`). Buffer cross-posting is live.
- Never include internal details: model names, env vars, database names, admin tools, how retention offers are triggered.
- `content/docs/build/mcp-reference/**` and `public/mcp-tools.json` are generated by `npm run gen:mcp`. Never edit them by hand.

## Page contract

Every page:

```mdx
---
title: Short title in sentence case
description: One sentence that says what the page answers. It is the page's entry in llms.txt, so make it specific.
---
```

- Start with the answer in 1 to 2 sentences. No "In this guide we will".
- One page answers one question. Link to the canonical page instead of re-explaining (for example, Sync is explained only in `using/concepts/sync`).
- Use headings an agent can jump to: `## How it works`, `## Steps`, `## Limits`, `## If it doesn't work`.
- Steps are numbered lists with the exact UI path in bold: **Settings → MCP**.
- Put numbers in tables, not prose.
- Plain words, short sentences, active voice. Explain a term the first time it appears.
- Links between pages use absolute docs paths: `/docs/using/concepts/sync`.
- Components available without import: `Callout` (`type="info" | "warn" | "error"`), `Cards`/`Card`, `Steps`/`Step`, `Tabs`/`Tab`, `Accordions`/`Accordion`. Prefer plain Markdown; components must still make sense when the page is read as Markdown.
- In MDX prose, `{`, `}` and `<` must be escaped or put in code spans.

## Commands

```bash
npm run dev       # http://localhost:3000

```
